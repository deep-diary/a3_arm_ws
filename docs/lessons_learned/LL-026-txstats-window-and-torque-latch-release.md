# LL-026 tx_stats 窗口旋转误读 + F42 latch 释放余量在慢速跟踪中不可达（残留 latch 钉死新轨迹）

- **日期**：2026-09-13
- **产品线**：Edge（can1 真机 7 自由度臂）
- **严重度**：中（①读数误判，无伤害；②残留 latch 钉死新轨迹——回程/park 卡死超时 → FAULT，若不修则 F40/F44 保护路径失效）

## 现象一：tx_stats 瞬时读显示轨迹帧几乎为 0

F46 验收时单次 `ros2 topic echo /a3/motor/tx_stats --once`：3 s/150 点轨迹刚下完，窗口显示 `tx_traj_total=7`——看似严重丢帧，实际轨迹期桥日志 TX window 行显示 `tx_traj=4098`（≈195 Hz/关节，99% 交付，限速丢弃仅 46 帧 0.7%）。

## 根因一

tx_stats 是 5 s 滚动窗口（先发布再清零），发布时刻与轨迹起止不同相：轨迹最后一截帧落入下一窗口，其计数要到下个窗口发布才可见。单次 `--once` 读取几乎必然与轨迹窗口错位。

## 修复一

帧率验收以**同时段桥日志 TX window 行**为准（日志逐帧统计、无窗口切分）；tx_stats 用于趋势与遥测。窗口对齐时重测 tx_traj_total=4098 与日志一致。

## 现象二：返回移动被残留力矩钳位 latch 钉死

F42 真机验收（L4/L6 两次 trip）后回程 move_to：**L4/L6 各只动 ~0.03 rad 即停**，日志无新 trip（反馈力矩远低于阈值）。F40/F44 的 safe-park 回 home 同样风险：被钉关节会卡到 park 超时 → FAULT。

## 根因二

F42 latch 释放条件要求「轨迹目标越过反馈位反向侧且 |mapped−fb| > release_margin（0.02 rad）」。慢速跟踪运动（3 s/150 点）跟踪滞后仅 ~0.006 rad（kp×滞后≈负载力矩）< 0.02——**目标永远到不了释放线，latch 永不释放**，新轨迹被钉在旧 trip 反馈位。

## 修复二

`motor_protocol_node` `OnTrajectory` 收到新轨迹时清空全部 latch（`torque_latch_active_`/`torque_latch_sign_` 清零）：**新轨迹 = 新意图**。保护不减弱——阻力仍在时钳位会在一个 tick 内按反馈力矩重新 trip。真机验证：修复后同一回程完整走完（L4→0.1605、L6→+0.0002）。

## 注意

- 任何「读数窗口」与「事件」不同相的场景（tx_stats 5 s 窗口、遥测降采样）读瞬时值都可能是尾巴/前沿切分——对照日志级证据再下结论。
- 状态型 latch（钳位、模式）必须定义与「新意图」的关系：新轨迹清 latch 比依赖释放条件更可靠；release margin 只负责同一意图内的反向放行，不可达时（慢速跟踪）latch 变成死锁。
- 设计释放条件前先估稳态跟踪滞后：kp=80 时 ~0.006 rad，小于任何合理 margin。
