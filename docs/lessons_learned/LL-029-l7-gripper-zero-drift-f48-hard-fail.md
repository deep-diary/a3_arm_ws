# LL-029 夹爪全开止点读数漂负触发 F48 硬校验 FAIL——单独重设零恢复（勿放宽限位）

- **日期**：2026-09-13
- **产品线**：Edge（真机 7J，L7 夹爪）
- **严重度**：中（开机即拦住使能；处理不当会掩盖标定漂移或引入止点残余力矩）

## 现象

阶段 1 编排层回归前跑 `scripts/a3_check_zero_frame.py`（F48）：其余 6 关节全在限位内，唯独 `L7_joint = -0.0228` 越下界（limit 0.0..1.8）→ HARD FAIL，使能门禁（`enable_position_check: true`）同步拒绝使能。读数连续（非断电多圈环绕）。

## 根因

L7 标定惯例是「全开位设零、闭合为正」。设零时刻手指被推到全开止点并受外力，零位实际落在**止点内侧 ~0.023 rad**；撤力后机构回弹到止点，读数即停在 -0.0228（比零更开）。之后任何「全开目标 0」的指令都会在止点处残留 kp×0.023 ≈ 1.8 Nm 的**闭合方向**力矩（固件 0x700B=1.0 Nm 硬限下呈持续 1 Nm 预紧压指）——即此前开合测试看到的「反向力矩」。

## 修复

趁桥 gate 关闭（power_sequence Idle，F32 互锁不拒 set_zero）给 L7 单独重设零：

```bash
ros2 service call /a3/motor/set_zero a3_can_bridge/srv/MotorCommand "{motor_id: 7, command: 3}"
# 必须逐关节读回校验（广播/单发都有丢帧先例）：motor_id 7 position_rad ≈ 0
```

重跑 F48：L7 = -0.0002，PASS。已存位姿（home/ready 中 L7≈0 表示「全开」）物理语义不变，无需重录。

## 为什么不放宽限位

- -0.0228 是一次设零的间隙产物，不是机械事实；把限位下界放宽（如 -0.05）等于把标定漂移固化进 URDF/F48/门禁三处安全配置，且与官方同源 URDF 限位分叉。
- 止点残余 1 Nm 预紧使 L7 长期发热、压指磨损，且幅值随每次设零漂移不可控。
- 全开止点归 0 后：止点处误差=0、无残余力矩，之后每次开机止点读数 ≈0，F48 自动 PASS。

## 注意

- 单独 set_zero 后**只影响该电机**，多圈窗口（zero_sta=1）不受影响；读数连续（未环绕）时无需重存 zero_sta。
- 开机 F48 HARD FAIL 先区分「连续小偏移（标定漂移，重设零）」与「±2π 量级跳变（断电环绕，回零位姿态重设零，LL-019 相关）」——两者处置不同。
- 真机编排层直连服务流（enable/move_to/disable）要求桥以 `use_power_sequence:=false` 启动：默认 true 时 gate 关闭会静默阻断轨迹流（skip_power_gate 计数增长），gate 打开（Running）时 F32 互锁又拒绝 enable/reset/set_zero。F40–F46 与阶段 1 回归均在此配置下验证。
