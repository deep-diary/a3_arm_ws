# LL-019 — 断电转动丢多圈环绕：zero_sta(0x7029) 窗口 + RS00 旧固件 0.0.3.4 读回坏但写生效

> **日期：** 2026-09-13
> **产品线：** Edge
> **环境：** RK3588（lubancat）+ can1 @ 1 Mbps + 真机 7 关节臂（L1–L3 RS00、L4–L7 EL05，ID 1–7）

## 现象

断电后手动转动各关节再上电（用户带回测试），多圈计数出现三种行为：

1. **未动的关节（L2/L3/L4）**：读数精确保持，断电不丢。
2. **正转的关节（L1/L5/L7）**：读数连续（符号与目测一致，幅度约 2× 目测值——用户目测误差，非系统偏差）。
3. **负转 ~22° 的 L6（EL05）**：真实 -0.3838 rad 读成 **+5.8994 rad（+338°）**，正好 +2π 环绕——用户担心的「-10° 变 350°」真实发生。

后续 L6 又转回零位附近后读数变成 **6.2830 = 2π**。这正是当年机器狗「上电暴动」的机理：目标只差几度，但反馈多读 300+°，kp×误差瞬间猛拉。

**修复验证（2026-09-13 同日晚）**：修正保存帧数据域后置 1 + 保存 → 断电负转各关节再上电：L5 **-0.8361**、L6 **-1.6068**、L1 **-0.6055**、L7 +0.8380 全部连续，负数正确保留，不再 +2π 环绕。

## 根因

- 电机上电时用**单圈编码器 + 多圈推算**恢复绝对角度，推算结果被映射进一个规范窗口；默认参数 `zero_sta`（0x7029）= 0 时窗口是 **0~2π**，所以任何负向转动都被折成 +2π 侧的大正角。
- `zero_sta=1` 时窗口变为 **-π~π**：±180° 内的断电转动都能被正确记录（L2 行程 0~3.67、L3 行程 -4.01~0 超出 ±π，这两个关节超 ±180° 的大转动仍会环绕）。
- **窗口只在重新上电重建多圈时生效**：运行中改 zero_sta 不会重推导当前读数（实测改完 L6 仍读 2π），效果要等下一次上电。
- **保存帧（类型 22）数据域不是全零**：协议文档规定数据域固定 `01 02 03 04 05 06 07 08`，全零**不触发保存**。2026-09-13 第一次上电验证全部 7 电机 zero_sta 回退 0（RAM 写当时生效过、flash 没存），L5/L6 断电负转再度环绕（+5.87/+5.34）。修正 save 数据后需再断电验证。
- **固件版本分裂**（实测，同为 0x7029 uint8 写）：
  - RS00 `0.0.3.4`（L1/L3）：**0x7029 读回恒 0（读路径坏/恒默认），但类型 18 写 + 类型 22 保存实际生效**。行为证据：L1 在正确保存后断电负转 ~0.38 rad，上电读 **-0.6055 连续**（若窗口仍为 0~2π 应读 ≈5.68）；L3 临时设零后断电负转，上电读 **-0.5200 连续**。判断以断电行为为准，**别信读回**——旧固件无需升级。
  - RS00 `0.0.3.19`（L2）：读写正常。
  - EL05 `10.5.0.1`（L4–L7）：读写正常，置 1 后断电负转读数连续保留（2026-09-13 实测：L5 +5.866 环绕态 → 断电负转 → 读 **-0.8361**；L6 +5.340 环绕态 → 读 **-1.6068**；L7 正转 +0.8380 连续）。
- **安全红线**：环绕读数超关节限位（如 L6=5.9 > ±1.57）时严禁使能——kp×误差会瞬间猛拉。使能前必须先 probe 校验读数全部落在限位内。

## 正确做法 / 规避

1. **出厂标定一次**：工装摆 URDF 零位 → `set_zero` 广播 → `set_param_u8` 广播 0x7029=1 → `save_param` 广播。之后正常使用（断电后不超 ±180° 转动）无需再对零。
2. **上电校验流程（已落地为 F48，2026-09-13）**：`scripts/a3_check_zero_frame.py` 限位硬检查（exit 1 严禁使能）+ 期望位姿软检查；`/a3/arm/enable` 内置限位门禁（越限/无 /joint_states 拒绝使能，`enable_position_check`）。发现环绕（读数超限）说明断电期间有人超范围转动 → 摆回 URDF 零位 → `/a3/arm/init` 重新对零（init 是恢复路径，越限只 WARN）。**禁止在读数超限时使能**。另：set_zero 广播可能丢帧（实测 L3 单独补发才归零），关键写操作后必须逐关节读回校验。
3. **旧固件电机**：RS00 0.0.3.4 的 0x7029 **读回恒 0 但写+保存生效**——置 1 后不要用读回判定成败，用断电行为验证；若行为仍环绕再考虑升级固件（≥0.0.3.19 读写正常）。
4. **不要用「每次上电除 L4 外全 set_zero」**：set_zero 把零位定义成当次上电姿态，每次上电零位帧都漂移，poses/FK 全部失效；且 L4 不重置会造成「新旧两套帧混用」更乱。该做法只适合无绝对位姿语义的机器狗（相对运动），不适合有 URDF 运动学的臂。
