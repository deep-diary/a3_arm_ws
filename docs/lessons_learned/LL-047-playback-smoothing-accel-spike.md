# LL-047 — 回放抖动根因是录制的加速度尖峰，不是伺服；播放时平滑解决

> **日期：** 2026-09-16
> **产品线：** Edge
> **环境：** RK3588 lubancat + ROS 2 Humble + reBot 平台

## 现象

示教回放肉眼「稍微抖动」。先怀疑伺服跟随差，实测 `/joint_states` 对齐回放指令后
**最优滞后 0.00 s、帧抖动中位数 2.9 mrad** → 伺服忠实复现。抖动源头在录制的数据本身：
手拖录制 50 Hz 数据天然带加速度尖峰（实测 L2 113 rad/s²、L3 82 rad/s²，jerk
8589/6242 rad/s³），伺服按指令使能 → 快速段上 L2/L3 出现 ±250–300 mrad 反相振荡。

## 根因

- 回放路径（`_playback_cb`）对录制点**原样**发布到 `/joint_group_effort_controller/joint_trajectory`，
  无任何低通；
- 手拖录制（ZERO_TORQUE 拖动）时人手不可能平滑 → 尖峰必然存在；
- **再示教不能解决**：重新录还会带同样的手抖尖峰。

## 正确做法 / 规避

回放时软件低通：`playback_smooth_samples`（默认 7）中心滑动平均，只动 positions、
保留 `time_from_start`；凸组合保证了不出录制包络、端点不动、路径几何扰动 ≤20 mrad。
实测 L2 118.9→9.5 rad/s²（-92%）、L3 86.3→7.4。`0/1` 关闭，热设置生效。
**教训：抖动先分「指令侧」与「反馈侧」，对齐回放指令查滞后/帧噪声（伺服健康的判据），
别用肉眼/加速度峰值直接归罪执行层。**

## 真机实测更新（2026-09-16，5J 真臂同控制器 A/B）

同一控制器上热切换 `playback_smooth_samples` 7→0 各跑一轮（平滑档跑两轮 r2/r3 验证可复现，
原始档 r4），对录制造 start 相位逐轮扫最优 τ 对齐后统计 body 段：

| 指标 | 平滑 on (r2/r3) | 原始 off (r4) |
|---|---|---|
| 跟踪 RMS L2 / L3 | 29 / 25、24 / 21 mrad | 42 / 40 mrad（↓≈30–40%） |
| 跟踪峰误差 L2 / L3 | 76–82 / 64–68 mrad | 128 / 101 mrad（↓≈35%） |
| 端部 L1 / L5 RMS | ≈3 / 0.3 mrad | 同 | 
| 反馈加加速度 p95 | ≈5.4–5.9 | ≈6.3–6.4 rad/s² |

**修正原判断的测量口径**：真臂反馈二阶差分加加速度两档都在 ~5–6 rad/s² 的**编码器噪声底**上，
峰值不降（伺服本身的负载/力矩滤波先吃掉了命令尖峰），所以平滑在真臂上可量化的收益不是"反馈加速度值"，
而是**跟踪保真度**：指令尖峰没了 → 伺服不"撵尖峰" → 反馈贴命令更紧。判据用**相位对齐后的跟踪误差**，
不要用反馈加速度峰值。平板感观上更稳即源于此。v7 默认不回退，`0/1` 双向热切换均生效。
