# LL-022 服务直驱使能后桥无目标流 → 电机静默保位失效（真机悬空臂瘫软）

- **日期**：2026-09-13
- **产品线**：Edge（can1 真机 7 自由度臂）
- **严重度**：高（误判「已使能并保持」，实际无力矩，依赖泡沫支撑才未掉臂）

## 现象

全臂 `/a3/arm/enable`（→ `/a3/motor/enable` 通信类型 3）返回 `ok (7 frame(s))`，编排层状态 READY、`/a3/arm_status` 位姿读数稳定，看起来「7/7 已使能、无漂移保持」。但用户目视机械臂处于瘫软状态（悬空位下方有泡沫支撑才没掉）。数分钟后 can1 总线上**只有 L7（夹爪）的流量**，L1–L6 无任何收发帧。

## 根因

1. **服务直驱使能不产生运控帧流**：`/a3/motor/enable`（类型 3）只让电机进入 MIT 运行模式，不填充桥的 `last_commanded_mit_rad_`（该数组只有轨迹/jog 路径会写入）。使能后若再无轨迹下发，L1–L6 的 `last_commanded` 恒为 NaN。
2. **LL-020 播种逻辑漏了「已使能但从未被指令」这一态**：`OnTxRefreshTimer` 播种条件为「模式未知或已知失能（mode 0）」；已知使能（mode 2）直接 `continue`（当初理由是避免与夹爪力控轨迹流抢总线）。于是 L1–L6 永远收不到任何帧。
3. **电机不主动上报**（LL-018）→ 无帧进 → 无 02 反馈出 → `/joint_states`/`/a3/motor/states` 数值冻结、`fresh=false`。冻结数值「看起来没漂移」掩盖了真相——**读任何 js 判状态的流程必须先验新鲜度**（LL-020 教训再次应验）。
4. 电机在 MIT 模式无帧流入 → 位置环无目标 → 无力矩输出（等效 kp=0），悬空臂自然下垂。本机固件**无通信看门狗**（事后解析 02 反馈帧扩展 ID bit22-23：mode 仍为 2，未掉到 0）。

## 诊断手段（用户提示的帧级确认法）

02 反馈帧 29-bit 扩展 ID：`bit28-24=通信类型(2)`、**`bit22-23=模式状态`（0 Reset / 1 Cali / 2 Motor 运行）**、`bit16-21=故障位`、`bit8-15=电机 CAN ID`、`bit0-7=主站 ID`。`candump can1` 抓总线 → 按 `(id>>8)&0xFF` 分电机、`(id>>22)&3` 读模式。对照 `/a3/motor/tx_stats` 的 `tx_hz`（哪个关节在发帧）与 `/a3/motor/states` 的 `fresh` 标志，三件套定位「桥在发谁、电机在不在、反馈新不新」。

## 修复

`OnTxRefreshTimer` 播种三态化（`motor_protocol_node.cpp`）：

1. **模式未知 / 已知失能**：维持原 LL-020 零增益保活播种（p=反馈位或 0，kp=kd=tau=0）；
2. **已知使能且反馈新鲜**：把目标**一次性锚定到最新反馈位**，用 runtime kp/kd/tau 真实保持——恢复帧流、反馈新鲜度并保位（零增益播种会让已使能电机完全卸力）；
3. **已知使能但反馈陈旧**：不盲发（不知实际位置，kp 保持会拉错位）。

修复后桥重启 8 s 内：7/7 `fresh=true`、`tx_stats.tx_hz≈47.2×7`、candump 可见每关节保持帧（kp=80/kd=2）+ 逐帧 02 应答。

## 衍生注意事项

- 保位是纯 P 控制：稳态误差 = τ_g/kp（kp=80 时约 1–2°），重力补偿入环（F9/C3）后自然消除。
- F42 力矩钳位限 3.0 Nm：若某姿态保持力矩 τ_g>3 Nm（本臂 L2 悬空姿态接近此量级），钳位 latch 会把目标反复钉在反馈位，表现为缓慢下爬——观察 `mtq_L{n}`，必要时运行时调高 `torque_protection_limit_nm`；重力补偿开启后 τ_ff 承担重力、实测 τ 回落，此问题消失。
- 服务直驱使能后**必须**有后续帧流（轨迹/jog 或本播种保持），否则电机「使能中但无力矩」。
